HTML Notes & Topics (Beginner to Advanced)

1. Introduction to HTML
  • What is HTML?
    HTML stands for HyperText Markup Language. It is the standard markup language used to create web pages and web applications.
    • HyperText: Text displayed on a computer or device that provides access to other text through links (hyperlinks).
    • Markup Language: A way to annotate text so that a computer can manipulate and display it differently. HTML uses tags like <h1>, <p>, etc.
    • HTML is not a programming language; it is a markup language for structuring content.
    • Browsers read HTML files and render them as web pages.
  • Why learn HTML?
    HTML is the backbone of all websites. Learning HTML is the first step for every web developer. It allows you to structure content and build the foundation for web design and development.
    • Every website uses HTML, regardless of the technology stack.
    • Understanding HTML helps you debug, customize, and optimize web pages.
    • HTML knowledge is essential for learning CSS, JavaScript, and frameworks like React or Angular.
    • It is easy to start and experiment with HTML using just a text editor and browser.
  • How HTML works
    HTML uses tags and elements to structure content. Tags like <h1>, <p>, and <a> define headings, paragraphs, and links.
    • HTML documents are plain text files with a .html extension.
    • Tags are enclosed in angle brackets: <tagname>...</tagname>
    • Most tags have an opening and closing tag, but some are self-closing (e.g., <img>).
    • Browsers parse HTML and display the structured content visually.
    • Example: 
        <h1>Welcome!</h1>
  <p>This is a paragraph.</p>
  <a href="https://example.com">Visit Example</a>
  • History and evolution of HTML
    HTML was created by Tim Berners-Lee in 1991. It has evolved from simple text formatting to supporting multimedia, APIs, and responsive design. The current version is HTML5.
    • 1991: First version of HTML published with basic tags for text and links.
    • HTML 2.0 (1995): Standardized the language and added forms.
    • HTML 3.2 & 4.01 (1997-1999): Introduced tables, scripting, and more formatting options.
    • XHTML (2000): Stricter syntax, based on XML.
    • HTML5 (2014): Added audio, video, canvas, semantic elements, APIs, and improved support for mobile and modern web apps.
    • HTML continues to evolve with new features and best practices.
  • HTML Syntax and Structure
    • HTML files start with <!DOCTYPE html> to declare the document type.
    • The root element is <html>, containing <head> (metadata) and <body> (visible content).
    • Indentation and comments (<!-- comment -->) help organize code.
    • Example structure: 
        <!DOCTYPE html>
  <html>
    <head>
      <title>Page Title</title>
    </head>
    <body>
      <h1>Hello World</h1>
      <p>This is a sample page.</p>
    </body>
  </html>
  • HTML in the Real World
    • All websites, from simple blogs to complex web apps, use HTML as their foundation.
    • HTML works together with CSS (for styling) and JavaScript (for interactivity).
    • Modern web development uses HTML templates, frameworks, and preprocessors, but the basics remain the same.
    • Understanding HTML helps you work with content management systems (WordPress, Joomla), email templates, and more.
2. Basic Document Structure
  • 2.1. The DOCTYPE Declaration

    The <!DOCTYPE html> declaration defines the document type and version of HTML. It must always be the very first line in your HTML files.

    Purpose: Tells the browser to render the page using HTML5 standards.
    Syntax: 

    <!DOCTYPE html>

    Note: <!DOCTYPE html> is not case sensitive but is conventionally written in uppercase.

    Without DOCTYPE: The browser may render the page in "quirks mode", leading to unexpected behaviors.

  • 2.2. The <html> Element and Language Attribute

    The <html> element wraps all content of your page and tells the browser that the content is an HTML document.
    Use the lang attribute to specify the language of your document for accessibility and SEO. 

    <html lang="en">
  ...all your HTML content...
</html>
    • Best Practice: Always set lang (e.g., en for English, sw for Kiswahili).
    • Benefit: Screen readers and search engines use this information.
  • 2.3. The <head> Section

    The <head> element contains meta-information about the document, links to CSS, scripts, and more. It is not displayed on the page.

    • 2.3.1. <title> Element

      The <title> element sets the title of your page as shown in the browser tab or window. 

      <title>My First Page</title>
    • 2.3.2. Meta Tags

      Meta tags provide metadata such as character set, author, description, and viewport settings. 

      <meta charset="UTF-8">
<meta name="description" content="Learn HTML basics">
<meta name="author" content="Your Name">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
      • charset: Encoding for the document (UTF-8 supports all characters).
      • description: Short summary for search engines.
      • author: Author of the page.
      • viewport: Ensures mobile-friendliness.
    • 2.3.3. Linking CSS Stylesheets

      Use the <link> element to link to external CSS files for styling your HTML. 

      <link rel="stylesheet" href="styles.css">

      Place CSS links in the <head> for best performance.

    • 2.3.4. Adding Internal Styles <style>

      For small CSS, you can use the <style> tag inside <head>. 

      <style>
  body { background: #f8f8f8; }
</style>
    • 2.3.5. Adding Favicon

      The <link rel="icon"> sets the small icon displayed in the browser tab. 

      <link rel="icon" href="favicon.ico">
    • 2.3.6. Linking JavaScript Files (head)

      You may link scripts in the head (rarely recommended unless defer or async is used): 

      <script src="main.js" defer></script>

      defer waits to execute until after HTML is parsed.

  • 2.4. The <body> Section

    The <body> element contains all content that is visible to users: text, images, links, forms, etc. 

    <body>
  <h1>Welcome!</h1>
  <p>This is my first web page.</p>
</body>
    • Tip: All visible content must be placed inside <body>.
    • Best Practice: Keep your structure clear and semantic.
  • 2.5. Putting It All Together: A Complete HTML5 Skeleton

    Here is a minimal but complete HTML5 template: 

    <!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>My First Page</title>
    <link rel="stylesheet" href="styles.css">
    <link rel="icon" href="favicon.ico">
  </head>
  <body>
    <h1>Hello, world!</h1>
    <p>Welcome to your first HTML document.</p>
  </body>
</html>
    • Start every HTML file with this basic structure.
    • Add more elements inside <body> as you learn new topics.
  • 2.6. Comments in HTML

    Use comments to explain your code or temporarily disable parts of your HTML. 

    <!-- This is a comment. Comments are not displayed in the browser. -->
    • Comments help you and others understand your code.
3. Headings, Paragraphs, and Text Formatting
  • 3.1. Headings: <h1> to <h6>

    Headings are used to organize content, provide hierarchy, and improve accessibility/SEO.

    • 3.1.1. Semantic Importance & Best Practices
      • Use only one <h1> per page (usually the title or main topic).
      • Lower levels (<h2>, <h3>, etc.) are used for subsections and sub-subsections.
      • Do NOT skip heading levels (e.g., do not jump from <h1> to <h4>).
      • Screen readers use headings for navigation.
      • Search engines use headings to index page structure and content topics.
    • 3.1.2. Visual Appearance & CSS Styling

      By default, browsers display <h1> as the largest and <h6> as the smallest. You can style headings using CSS: 

      h1 { color: #E44D26; font-size: 2.5em; }
h2 { color: #FF784E; }
    • 3.1.3. Example: Nested Headings 
      <h1>HTML Basics</h1>
  <h2>Text Elements</h2>
    <h3>Headings</h3>
    <h3>Paragraphs</h3>
  <h2>Lists</h2>
  • 3.2. Paragraphs: <p>
    • 3.2.1. Creating Paragraphs and Whitespace

      The <p> tag wraps blocks of text into paragraphs. Browsers ignore whitespace and line breaks inside HTML, so always use <p> for separate paragraphs. 

      <p>First paragraph.</p>
<p>Second paragraph.</p>
    • 3.2.2. Paragraphs and CSS

      You can style paragraphs using CSS, for example: 

      p {
  line-height: 1.6;
  color: #444;
  margin-bottom: 16px;
}
    • 3.2.3. Nesting and Validity

      Do NOT nest block elements inside <p>. For example, this is invalid: 

      <p>Paragraph start
  <ul>...</ul>
</p>

      Instead, close the paragraph before starting a new block element.

  • 3.3. Line Breaks <br> and Horizontal Rules <hr>
    • 3.3.1. <br> for Inline Breaks

      Use <br> only for single line breaks, such as in addresses or poetry. 

      <address>
  WAKWANZAGP
      
  123 Main Street
      
  Dar es Salaam, TZ
</address>
    • 3.3.2. <hr> for Thematic Breaks

      The <hr> tag represents a thematic break or change in topic. 

      <p>Section one...</p>
<hr>
<p>Section two...</p>
    • 3.3.3. Styling <hr> and <br> with CSS 
      hr {
  border: none;
  border-top: 2px dashed #ff784e;
  margin: 32px 0;
}
  • 3.4. Text Formatting Tags
    • 3.4.1. <strong> vs <b> (Bold)

      <strong> means "important" (semantic), <b> is just stylistic. 

      <strong>Warning: Do not close the file!</strong>
<b>This is just bold text.</b>
      • Accessibility: <strong> will be announced as "important" by screen readers.
      • Use <strong> for emphasis on meaning, <b> for visual styling only.
    • 3.4.2. <em> vs <i> (Italic)

      <em> means "emphasized" (semantic), <i> is just stylistic. 

      <em>You must remember this.</em>
<i>This is just italic text.</i>
      • Accessibility: <em> is read with emphasis by screen readers.
    • 3.4.3. <mark> (Highlight)

      <mark> highlights text with a yellow background by default. 

      <p>This is <mark>important</mark> for the exam.</p>
    • 3.4.4. <small> (Small Print)

      <small> displays text in a smaller font size, often used for disclaimers or notes. 

      <small>*Terms and conditions apply.</small>
    • 3.4.5. <sup> and <sub> (Superscript and Subscript)

      <sup> is used for superscript, <sub> for subscript (common in math/science). 

      E = mc<sup>2</sup>   
H<sub>2</sub>O
    • 3.4.6. Combining Formatting Tags 
      <p>This is <strong><em>very important</em></strong> text.</p>

      You can nest tags for combined effects.

  • 3.5. Special Characters (Entities)
    • 3.5.1. Common HTML Entities 
      &nbsp;   
&copy;   
&lt;     
&gt;     
&amp;    
&quot;
    • 3.5.2. When to Use Entities
      • When you want to display reserved HTML characters (like <, >, &, ").
      • When adding copyright, trademark, and math symbols.
      • For invisible spaces (&nbsp;).
    • 3.5.3. Example: Using Entities in Context 
      <p>This is how you write &lt;div&gt; in HTML.</p>
<p>Price: 100 &euro; or 120 &dollar;</p>
<p>Non-breaking space: word1&nbsp;word2</p>
    • 3.5.4. External Resources for Entities

      For more entities, see: HTML Entity Reference

4. Links and Images
  • 4.1. Creating Links with <a>
    • 4.1.1. Basic Link Syntax

      The <a> tag (anchor) is used to create hyperlinks to other web pages, files, or resources. 

      <a href="https://example.com">Visit</a>
    • 4.1.2. Internal vs. External Links

      Internal link: Goes to another page within your website. 

      <a href="about.html">About Us</a>

      External link: Goes to a different website. 

      <a href="https://wikipedia.org">Wikipedia</a>
    • 4.1.3. Opening Links in a New Tab

      Use target="_blank" to open the link in a new browser tab/window. For security, add rel="noopener noreferrer". 

      <a href="https://example.com" target="_blank" rel="noopener noreferrer">Open Example in New Tab</a>
    • 4.1.4. Anchor Links (Jump Links)

      Link to a specific part of the same page using an element's id. 

      <a href="#section2">Go to Section 2</a>
...
<h2 id="section2">Section 2</h2>
    • 4.1.5. Linking to Email and Phone 
      <a href="mailto:info@example.com">Email Us</a>
<a href="tel:+255700000000">Call Now</a>
    • 4.1.6. Styling Links with CSS 
      a:link { color: #0057b7; }
a:visited { color: #ff784e; }
a:hover { color: #18e1d9; text-decoration: underline; }
a:active { color: #e44d26; }
  • 4.2. Images: <img> Tag
    • 4.2.1. Basic Image Syntax 
      <img src="logo.png" alt="Logo">

      src: Path/URL to the image
      alt: Alternative text for screen readers and when the image cannot be displayed

    • 4.2.2. Image Attributes: width, height, title 
      <img src="logo.png" alt="Logo" width="150" height="80" title="Website Logo">
      • width and height: Set the size (in pixels)
      • title: Shows tooltip on mouse hover
    • 4.2.3. Responsive Images (CSS) 
      img {
  max-width: 100%;
  height: auto;
}
      • Prevents images from overflowing their container on smaller screens.
    • 4.2.4. Accessibility with alt text

      Descriptive alt text helps visually impaired users understand image content. 

      <img src="team.jpg" alt="Team working on a project">

      Decorative images: Use alt="" for purely decorative images.

    • 4.2.5. Image Optimization and Formats
      • Use appropriate formats: JPEG/JPG (photos), PNG (transparency), SVG (vector), WebP (modern, fast).
      • Compress images to reduce file size and page load times (use tools like Squoosh).
      • Use srcset for responsive and high-resolution images: 
        <img src="photo.jpg"
     srcset="photo.jpg 1x, photo@2x.jpg 2x"
     alt="Landscape">
    • 4.2.6. SEO and Semantic Images: <figure> and <figcaption> 
      <figure>
  <img src="award.jpg" alt="Award Ceremony">
  <figcaption>Award Ceremony, June 2025</figcaption>
</figure>
      • <figure> groups an image with its caption (<figcaption>).
      • Helps search engines and users understand context and meaning.
Summary Example: 
<a href="https://wakwanza.co.tz" target="_blank" rel="noopener noreferrer">Visit WAKWANZA GPT</a>
<img src="wakwanza-logo.png" alt="WAKWANZA GPT Logo" width="150" title="WAKWANZA GPT">
5. Lists
  • 5.1. Unordered Lists: <ul>

    Unordered lists display items with bullet points. Each item uses the <li> tag. 

    <ul>
  <li>Apple</li>
  <li>Banana</li>
  <li>Orange</li>
</ul>
    • By default, bullets are solid circles, but you can change them with CSS (e.g. list-style-type: square;).
    • Use unordered lists for items with no specific order.
  • 5.2. Ordered Lists: <ol>

    Ordered lists display items with numbers or letters. Each item uses the <li> tag. 

    <ol>
  <li>Step one</li>
  <li>Step two</li>
  <li>Step three</li>
</ol>
    • Default type is numbers; you can change to letters or Roman numerals with type attribute: 
      <ol type="A">...</ol>   <!-- A, B, C -->
<ol type="a">...</ol>   <!-- a, b, c -->
<ol type="I">...</ol>   <!-- I, II, III -->
<ol type="i">...</ol>   <!-- i, ii, iii -->
    • Use start attribute to specify a starting number: 
      <ol start="5">...</ol>
  • 5.3. Description Lists: <dl>, <dt>, <dd>

    Description lists are used for pairs of terms and definitions. 

    <dl>
  <dt>HTML</dt>
  <dd>HyperText Markup Language</dd>
  <dt>CSS</dt>
  <dd>Cascading Style Sheets</dd>
</dl>
    • <dt> is the term, <dd> is the description.
    • Good for glossaries, FAQs, or attribute-value pairs.
  • 5.4. Nested Lists (Lists inside Lists)

    You can nest any list type inside another by placing a new <ul>, <ol>, or <dl> inside an <li> or <dd>. 

    <ul>
  <li>Fruits
    <ul>
      <li>Apple</li>
      <li>Banana</li>
    </ul>
  </li>
  <li>Vegetables</li>
</ul>

    You can mix list types: 

    <ol>
  <li>First
    <ul>
      <li>Subitem 1</li>
      <li>Subitem 2</li>
    </ul>
  </li>
  <li>Second</li>
</ol>
    • Indent nested lists for readability and better structure.
  • 5.5. Styling Lists with CSS 
    /* Remove bullets */
ul {
  list-style-type: none;
  padding: 0;
}
/* Custom bullet */
ul.custom-bullet li::before {
  content: "★ ";
  color: orange;
}
/* Numbered circles for ordered lists */
ol {
  list-style-type: decimal-leading-zero;
}
    • Use list-style-type and ::before pseudo-element for custom styles.
  • 5.6. Accessibility Tips for Lists
    • Always use semantic list tags for navigation menus and groups of related items.
    • Screen readers interpret <ul>, <ol>, and <dl> correctly and announce the number of items.
    • Avoid using lists for layout purposes; use CSS Grid or Flexbox instead.
6. Tables
  • 6.1. Basic Table Structure: <table>, <tr>, <th>, <td>

    Tables are used to display data in rows and columns.

    • <table>: Table container
    • <tr>: Table row
    • <th>: Table header cell
    • <td>: Table data cell

    <table>
  <tr>
    <th>Name</th>
    <th>Age</th>
  </tr>
  <tr>
    <td>Alice</td>
    <td>21</td>
  </tr>
</table>

    Tables can have any number of rows and columns.

  • 6.2. Table Headers, Captions, and Summaries
    • 6.2.1. Table Headers: <thead>, <tbody>, <tfoot>

      Use <thead> for header rows, <tbody> for main data, and <tfoot> for summary/footer rows. 

      <table>
  <thead>
    <tr><th>Product</th><th>Price</th></tr>
  </thead>
  <tbody>
    <tr><td>Pen</td><td>1000</td></tr>
    <tr><td>Book</td><td>3000</td></tr>
  </tbody>
  <tfoot>
    <tr><td>Total</td><td>4000</td></tr>
  </tfoot>
</table>
    • 6.2.2. Table Caption

      The <caption> tag provides a title for the table, improving accessibility and understanding. 

      <table>
  <caption>Student List</caption>
  ...
</table>
    • 6.2.3. Table Summary (Accessibility)

      For accessibility, you can use summary (deprecated) or better, add aria-label or aria-describedby for screen readers. 

      <table aria-label="Monthly sales data">...</table>
  • 6.3. Rowspan and Colspan

    Use rowspan and colspan attributes to make cells span multiple rows or columns. 

    <table border="1">
  <tr>
    <th rowspan="2">Name</th>
    <th colspan="2">Contact</th>
  </tr>
  <tr>
    <td>Email</td>
    <td>Phone</td>
  </tr>
  <tr>
    <td>Alice</td>
    <td>alice@email.com</td>
    <td>123456</td>
  </tr>
</table>
    • rowspan="n": Cell spans n rows.
    • colspan="n": Cell spans n columns.
  • 6.4. Styling Tables with CSS 
    table {
  border-collapse: collapse;
  width: 100%;
}
th, td {
  border: 1px solid #ccc;
  padding: 8px 12px;
  text-align: left;
}
th {
  background: #e44d26;
  color: #fff;
}
tr:nth-child(even) {
  background: #f8f8f8;
}
caption {
  font-weight: bold;
  margin-bottom: 8px;
}
    • Use border-collapse: collapse; to merge table borders.
    • Alternate row colors with :nth-child(even) for readability.
    • Style caption to make table titles stand out.
  • 6.5. Accessibility and Best Practices
    • Always use <th> for header cells, and scope="col" or scope="row" for clarity: 
      <th scope="col">Name</th>
<th scope="row">Alice</th>
    • Use <caption> and ARIA attributes for better screen reader support.
    • Keep tables simple for accessibility. Only use complex structures (rowspan/colspan) when necessary.
    • Use tables for tabular data, not for layout/design.
  • 6.6. Complete Example 
    <table aria-label="Student List">
  <caption>Student List</caption>
  <thead>
    <tr><th>Name</th><th>Age</th><th>Grade</th></tr>
  </thead>
  <tbody>
    <tr><td>Alice</td><td>21</td><td>A</td></tr>
    <tr><td>Bob</td><td>22</td><td>B+</td></tr>
  </tbody>
</table>
7. Forms and Inputs
  • 7.1. Form Structure: <form>, <input>, <textarea>, <button>

    The <form> element wraps all form controls and can send user data to a server. 

    <form action="/submit" method="post">
  <input type="text" name="username">
  <textarea name="message"></textarea>
  <button type="submit">Send</button>
</form>
    • action: URL where data is sent.
    • method: HTTP method (get or post).

    Pro Tip: If action is omitted, data is sent to the same page. Use enctype for file uploads.

  • 7.2. Input Types: text, password, email, number, checkbox, radio, file, date, etc. 
    <input type="text" name="fullname" placeholder="Enter your name">
<input type="password" name="pass">
<input type="email" name="email">
<input type="number" name="age" min="1" max="120">
<input type="checkbox" name="subscribe" checked> Subscribe
<input type="radio" name="gender" value="male"> Male
<input type="radio" name="gender" value="female"> Female
<input type="file" name="resume" accept=".pdf,.docx">
<input type="date" name="birthdate">
<input type="range" min="0" max="10" step="1">
<input type="color" name="favcolor">
    • Use accept to specify allowed file types.
    • Use placeholder for hints inside text inputs.
    • Use checked for default-checked checkboxes/radios.
    • Use step for controlling increments in numeric/range inputs.
    • There are more types: tel, url, search, month, week, time, datetime-local, hidden, etc.

    Beyond Basic: Combine datalist for autocomplete, pattern for regex validation, multiple for multi-file uploads. 

    <input list="browsers" name="browser">
<datalist id="browsers">
  <option value="Chrome">
  <option value="Firefox">
  <option value="Edge">
</datalist>
  • 7.3. Labels, Accessibility, and ARIA 
    <label for="email">Email Address:</label>
<input type="email" id="email" name="email" aria-required="true">
    • Connect labels to inputs using for (label) and id (input).
    • Use aria-required="true", aria-label, and aria-describedby for screen readers.
    • Group related inputs with <fieldset> and <legend> for better accessibility: 
      <fieldset>
  <legend>Personal Info</legend>
  <label>Name: <input type="text"></label>
</fieldset>
    • Tabindex and accesskey let users navigate forms with keyboard shortcuts.
  • 7.4. Form Validation: Required, Pattern, Min/Max, Custom Validity
    • 7.4.1. HTML5 Built-in Validation 
      <input type="email" required>
<input type="password" minlength="8" maxlength="32" required>
<input type="text" pattern="[A-Za-z]{3,}" title="At least 3 letters">
<input type="number" min="1" max="10">
      • required: Cannot submit if empty.
      • pattern: Regular expression for validation.
      • min, max, step: For numbers and dates.
    • 7.4.2. Custom Validation with JavaScript 
      <input id="custom" required>
<span id="errmsg"></span>
<script>
  document.getElementById('custom').addEventListener('input', function(e) {
    if(this.value.length < 5) {
      this.setCustomValidity('At least 5 characters required.');
      document.getElementById('errmsg').textContent = 'At least 5 characters required.';
    } else {
      this.setCustomValidity('');
      document.getElementById('errmsg').textContent = '';
    }
  });
</script>
      • Use setCustomValidity() for custom error messages.
      • Display error messages dynamically.
      • Use novalidate on <form> to disable HTML5 validation and do it all in JS.

8. Semantic Elements
  • 8.1. What are Semantic Elements?

    Semantic elements clearly describe their meaning in a human- and machine-readable way. Unlike <div> and <span>, semantic elements indicate the role of their content.

    • Helps browsers, search engines, and assistive technologies understand page structure.
    • Improves code readability and maintainability.
    • Enhances SEO and accessibility.

    <li><a href="/about">About</a></li>
  </ul>
</nav>
    • <main>

      Represents the dominant content of the body. There should be only one <main> per page. 

      <main>
  <h2>Welcome to My Site</h2>
  <p>This is the core page content.</p>
</main>
    • <section>

      Defines a generic standalone section of content, usually with a heading.

  <h3>Features</h3>
  <ul>
    <li>Fast</li>
    <li>Reliable</li>
  </ul>

      <article>
  <h2>Breaking News</h2>

      <aside>
  <h4>Related Article</h4>

10. Block vs Inline Elements
  • 10.1. What Are Block Elements?

    Block elements create a new "block" on the page, taking up the full width available and starting on a new line. They often contain other block or inline elements.

    • Common block elements: <div>, <p>, <h1>–<h6>, <ul>, <ol>, <li>, <table>, <form>, <section>, <nav>, <header>, <footer>
    • Example: 
      <div>Block 1</div>
<div>Block 2</div>

      Each <div> starts on a new line.

    • Style: By default, block elements have display: block; in CSS.
  • 10.2. What Are Inline Elements?

    Inline elements do not start on a new line. They only take up as much width as necessary and flow within block elements or alongside other inline elements.

    • Common inline elements: <span>, <a>, <img>, <strong>, <em>, <code>, <input>, <label>
    • Example: 
      This is <span>inline</span> and <a href="#">so is this link</a>.

      Inline elements are placed within the flow of surrounding text.

    • Style: By default, inline elements have display: inline; in CSS.
  • 10.3. How Block and Inline Elements Affect Layout
    • Block elements: Always start on a new line; stack vertically. Can contain other block or inline elements. 
      <div>
  <p>This is a paragraph inside a block element.</p>
  <a href="#">Link</a> is allowed here as well.
</div>
    • Inline elements: Do not break the flow; can only contain other inline elements or text (not block elements). 
      <span>This is inline <strong>and bold</strong> text.</span>
    • Mixing: You cannot put block elements directly inside inline elements (invalid HTML). 
      <span>
  <div>Invalid!</div>
</span>
  • 10.4. Inline-Block and Other Display Types

    The display: inline-block; property allows an element to flow inline like an inline element, but also accept width, height, and vertical margins like a block element. 

    <span style="display: inline-block; width: 150px; background: #FFEB3B;">Inline-block element</span>
    • Useful for buttons, navigation items, and custom layouts.
    • Other display types include flex and grid for advanced layouts.
  • 10.5. Customizing Display with CSS 
    /* Make a block element behave like inline */
div.inline {
  display: inline;
  background: #b2ebf2;
}

/* Make an inline element behave like a block */
span.block {
  display: block;
  background: #ffe082;
}
    • You can change how any element behaves in the layout by changing its display property.
    • Be careful: this affects how elements interact with others around them.
  • 10.6. Real-World Examples and Use Cases
    • Navigation menus: 
      <nav>
  <ul>
    <li style="display:inline-block;"><a href="#">Home</a></li>
    <li style="display:inline-block;"><a href="#">About</a></li>
  </ul>
</nav>
    • Buttons in a toolbar: 
      <span style="display: inline-block; border:1px solid #ccc; padding:4px;">Button 1</span>
<span style="display: inline-block; border:1px solid #ccc; padding:4px;">Button 2</span>
    • Responsive images: 
      <img src="photo.jpg" alt="Photo" style="display:block; max-width:100%;">

    • Use block elements for logical grouping and structure (headings, sections, navigation, articles).

11. HTML Entities and Symbols
  • 11.1. What are HTML Entities?

    • To insert symbols not available on your keyboard, like ©, ™, €, →, etc.
    • To include invisible or whitespace characters, like non-breaking space (&nbsp;).
    • To ensure your page renders correctly across all browsers and encodings.
    • Example Usage: 
      <p>Use &lt;code&gt; tags for code.</p>
<p>Copyright &copy; 2025 WAKWANZA GPT</p>
<p>Price: 20&euro; or 25&dollar;</p>

13. Linking CSS and JavaScript
  • 13.1. Linking External CSS Files

    Use <link rel="stylesheet" href="style.css"> in the <head> section to attach external CSS files. 

    <head>
  <link rel="stylesheet" href="style.css">
</head>
    • Multiple CSS files can be linked; they are loaded in order.
    • Use for site-wide/global styles.
    • Can also include external libraries (e.g., Google Fonts, Bootstrap): 
      <link rel="stylesheet" href="https://fonts.
      googleapis.com/css?family=Roboto">
<link rel="stylesheet" href="https://cdn.
      jsdelivr.net/npm/bootstrap/dist/css/bootstrap.min.css">
    • You can add media attribute for responsive design: 
      <link rel="stylesheet" href="print.css" media="print">
  • 13.2. Internal CSS (<style> Tag)

    Define CSS rules directly within your HTML file using the <style> tag, usually in the <head>. 

    <head>
  <style>
    body { background: #f8f8f8; }
    h1 { color: #e44d26; }
  </style>
</head>
    • Good for page-specific or prototype styles.
    • Avoid large blocks of internal CSS in production—prefer external files for maintainability.
  • 13.3. Inline Styles (style attribute)

    Apply CSS directly to an element using the style attribute. 

    <h2 style="color: #18e1d9; margin-top: 24px;">Hello Inline Style!</h2>
    • Only affects the specific element.
    • Use sparingly; can make maintenance difficult if overused.
    • Helpful for quick testing or dynamic styling via JavaScript.
  • 13.4. Linking External JavaScript Files

    Use <script src="script.js"></script> to load external JavaScript files. 

    <body>
  ...
  <script src="script.js"></script>
</body>
    • Place scripts before </body> for better performance (so the page loads before JS runs).
    • You can use defer or async attributes: 
      <script src="app.js" defer></script>  <!-- Runs after parsing HTML -->
<script src="analytics.js" async></script>  <!-- Runs as soon as ready -->
    • External scripts can include libraries (e.g., jQuery, React, CDN scripts): 
      <script src="https://cdn.jsdelivr.net/npm/vue/dist/vue.min.js"></script>
  • 13.5. Internal JavaScript (<script> Tag)

    Write JavaScript directly inside your HTML using the <script> tag. 

    <script>
  console.log('Hello from internal JS!');
  document.getElementById('btn').onclick = function() {
    alert('Button clicked!');
  }
</script>
    • Can be placed in <head> or <body>. For DOM-manipulating code, place after elements are loaded or use DOMContentLoaded event.
    • Good for simple scripts or inline event handlers.
  • 13.6. Inline JavaScript (on* attributes)

    Inline JavaScript uses event attributes directly on elements (e.g., onclick, onchange). 

    <button onclick="alert('Hi!')">Click Me</button>
    • Quick for demos, but separate JS for maintainable code.
    • Mixing behavior and structure is discouraged in modern development—prefer external scripts and event listeners.
  • 13.7. Loading Order, Performance, and Best Practices
    • Place CSS in the <head> for fast rendering and to prevent "flash of unstyled content" (FOUC).
    • Place JavaScript before </body>, or use defer for scripts in <head> to avoid blocking rendering.
    • Minimize inline CSS/JS for better caching and separation of concerns.
    • Group related styles/scripts into single files to reduce HTTP requests.
    • Use Content Delivery Networks (CDNs) for popular libraries to leverage caching.
    • Avoid <style> and <script> in the middle of your HTML body for clarity and maintainability.
  • 13.8. Advanced: Dynamic Imports, Preloading, and Conditional Loading
    • Preloading CSS/JS for performance: 
      <link rel="preload" href="style.css" as="style">
<link rel="preload" href="main.js" as="script">
    • Media Queries and Alternate Stylesheets: 
      <link rel="stylesheet" href="dark.css" media="(prefers-color-scheme: dark)">
<link rel="alternate stylesheet" href="large.css" title="Large Text">
    • JavaScript dynamic imports (ES6): 
      <script type="module">
  import('./feature.js').then(module => {
    module.loadFeature();
  });
</script>
    • Conditional loading for legacy browsers: 
      <!--[if lt IE 9]>
  <script src="oldie.js"></script>
<![endif]-->

14. Accessibility (a11y)
  • 14.1. Descriptive alt Attributes for Images

    The alt attribute provides alternative text for images, allowing screen readers to convey image meaning to visually impaired users. 

    <img src="logo.png" alt="Company logo">
    • Use clear, concise descriptions for informative images.
    • Use alt="" (empty) for purely decorative images.
    • Avoid phrases like "image of..." or "picture of...".

    Example:
    <img src="award.jpg" alt="Team receiving the 2025 Innovation Award">

  • 14.2. Semantic HTML for Screen Readers

    Semantic elements (<header>, <nav>, <main>, <section>, <footer>, etc.) help assistive technologies understand page structure. 

    <nav aria-label="Main navigation">
  <ul>
    <li><a href="#home">Home</a></li>
    <li><a href="#about">About</a></li>
  </ul>
</nav>
    • Use headings (<h1>–<h6>) in a logical order.
    • Use <label> for form fields and for/id pairs for clarity.
    • Landmark roles (role="navigation", role="main") can enhance navigation for assistive tech.
  • 14.3. Tabindex, ARIA Roles, and Labels
    • Tabindex: Controls keyboard navigation order.
      <button tabindex="1">First</button>
<button tabindex="2">Second</button>
      • tabindex="0" = natural tab order
      • tabindex="-1" = focusable but not tab-navigable
    • ARIA Roles: Add semantic meaning or expose custom controls. 
      <div role="alert">Error: Invalid input.</div>
<nav role="navigation">...</nav>
    • ARIA Labels: Improve screen reader descriptions. 
      <button aria-label="Close modal window">×</button>
    • aria-live regions announce dynamic content changes. 
      <div aria-live="polite">You have new messages.</div>
    • aria-describedby and aria-labelledby connect inputs and their explanations or labels. 
      <input id="search" aria-describedby="search-desc">
<span id="search-desc">Type and press enter to search.</span>
  • 14.4. Color Contrast and Keyboard Navigation
    • Contrast: Ensure text/background color contrast ratio of at least 4.5:1 for normal text and 3:1 for large text.
      • Test with tools like WebAIM Contrast Checker.
      • Do not rely on color alone to convey meaning (use icons, text, or patterns).
    • Keyboard Navigation: All interactive elements (links, buttons, forms) must be reachable and usable with only the keyboard (Tab, Shift+Tab, Enter, Space).
      • Use visible focus indicators (outline, border, etc.).
      • Test navigation order and functionality without a mouse.
      • Avoid using display: none; or visibility: hidden; on focusable elements unless intentionally hidden from all users.
    • Skip Links: Provide "Skip to content" links at the top of the page for faster navigation. 
      <a href="#maincontent" class="skip-link">Skip to main content</a>
  • 14.5. Beyond: Testing and Best Practices
    • Test with screen readers (NVDA, JAWS, VoiceOver).
    • Use automated tools (axe, Lighthouse, WAVE) for quick audits.
    • Follow the WCAG guidelines.
    • Provide captions/transcripts for audio/video.
    • Ensure focus management for modals/popups (trap focus inside dialogs).
    • Keep your markup clean and semantic for maximal accessibility.

15. Responsive Design Basics
  • 15.1. The Viewport Meta Tag

    The <meta name="viewport"> tag ensures your page scales correctly on all devices. 

    <head>
  <meta name="viewport" content="width=device-width, initial-scale=1">
</head>
    • width=device-width sets the viewport to match the device’s width.
    • initial-scale=1 sets the initial zoom level.
    • Other options: maximum-scale, user-scalable.
    • Always include this tag in mobile-friendly sites.
  • 15.2. Flexible Images and Media

    Make images, videos, and other media scale with their container to prevent overflow and horizontal scrolling.

    • CSS for Images: 
      img, video, iframe {
  max-width: 100%;
  height: auto;
  display: block;
}
    • Picture Element for Responsive Images: 
      <picture>
  <source srcset="image-large.jpg" media="(min-width: 800px)">
  <source srcset="image-small.jpg" media="(max-width: 799px)">
  <img src="image-small.jpg" alt="A responsive example">
</picture>
      • Use srcset and sizes for high-DPI and bandwidth optimization.
    • Responsive Embeds (e.g., YouTube): 
      <div style="position:relative; padding-bottom:56.25%; height:0;">
  <iframe src="https://www.youtube.com/embed/ID" 
          style="position:absolute; top:0; left:0; width:100%; height:100%;" 
          frameborder="0" allowfullscreen></iframe>
</div>
  • 15.3. CSS Media Queries (Overview & Examples)

    Media queries let you apply CSS rules based on screen size, orientation, resolution, and more. 

    /* Basic syntax */
@media (max-width: 600px) {
  body {
    font-size: 16px;
    background: #f8f8f8;
  }
}

/* Multiple conditions */
@media (min-width: 601px) and (max-width: 1200px) {
  body {
    font-size: 18px;
  }
}
    • Common breakpoints: 480px (mobile), 768px (tablet), 1024px (laptop), 1200px+ (desktop).
    • You can target orientation: 
      @media (orientation: landscape) { ... }
    • You can also use media queries for print and dark mode: 
      @media print {
  body { color: black; background: white; }
}
@media (prefers-color-scheme: dark) {
  body { background: #222; color: #eee; }
}
  • 15.4. Mobile-First vs. Desktop-First Approaches
    • Mobile-First: Write base styles for mobile, then add media queries for larger screens. 
      /* Mobile (default) */
body { font-size: 16px; }
/* Tablet and up */
@media (min-width: 768px) { body { font-size: 18px; } }
    • Desktop-First: Write base styles for desktop, then use max-width media queries for smaller screens. 
      /* Desktop (default) */
body { font-size: 18px; }
/* Mobile */
@media (max-width: 767px) { body { font-size: 16px; } }
    • Mobile-first is generally preferred for performance and progressive enhancement.
  • 15.5. Responsive Layout Techniques
    • Fluid Grids: Use percentages instead of fixed units. 
      .container { width: 90%; max-width: 1200px; margin: auto; }
    • Flexbox and Grid: Modern layout modules for easy responsive design. 
      /* Flexbox example */
nav ul {
  display: flex;
  flex-wrap: wrap;
  gap: 1em;
}

/* CSS Grid example */
.grid {
  display: grid;
  grid-template-columns: 1fr 1fr;
}
@media (max-width: 600px) {
  .grid { grid-template-columns: 1fr; }
}
    • Hide/show content responsively: 
      @media (max-width: 500px) {
  .hide-mobile { display: none; }
}

16. HTML APIs and Advanced Elements
  • 16.1. <canvas>: Drawing Graphics with JavaScript

    The <canvas> element provides a drawable region in HTML, accessible via JavaScript for dynamic, scriptable rendering of 2D (and 3D with WebGL) graphics.

  Your browser does not support the canvas element.

  ctx.fillStyle = 'orange';

  ctx.strokeStyle = 'blue';
  ctx.lineWidth = 4;
  ctx.strokeRect(70, 60, 80, 40);
  ctx.beginPath();
  ctx.arc(110, 80, 20, 0, 2 * Math.PI);
  ctx.fillStyle = "green";
  ctx.fill();
</script>
    • Use for dynamic charts, games, image processing, and more.

</svg>

    • SVG elements can be animated and interact with user input.

    • <progress> element: Shows the completion of a task. 
      <progress value="70" max="100">70%</progress>

        <progress max="100">Loading...</progress>
    • <meter> element: Indicates a scalar value within a known range (e.g., disk usage, test scores). 
      <meter value="0.5" min="0" max="1" low="0.3" high="0.8" optimum="0.7">50%</meter>

17. SEO Fundamentals

What is SEO?

SEO (Search Engine Optimization) is the practice of optimizing your website and its content to appear higher in search engine results (like Google or Bing) for relevant search queries. The goal is to attract more organic (unpaid) visitors by making your pages more visible and relevant for what people search.

  • Main goal: Increase visitors to your website through unpaid (organic) search results.
  • How it works: Search engines use bots ("crawlers") to scan web pages and rank them based on relevance, usability, speed, and authority.
  • Why is it important? Higher rankings mean more visitors, users, or customers—without paying for ads.
  • Main areas of SEO:
    • On-page SEO: Optimizing your HTML, content, meta tags, and images.
    • Off-page SEO: Building links (backlinks) from other reputable sites.
    • Technical SEO: Improving site speed, mobile-friendliness, and making sure search engines can crawl your site easily.
Example:
If you have a page about “homemade pizza recipes” and you optimize it well, someone searching for that phrase is more likely to find your page high in Google's results.

  • 19.2. Text Direction: dir="ltr" and dir="rtl"

    The dir attribute specifies the direction of text: left-to-right (ltr, default) or right-to-left (rtl). It's essential for supporting languages like Arabic, Hebrew, Persian, and Urdu. 

    <html lang="ar" dir="rtl">
  <head>...</head>
  <body>...</body>
</html>
    • Can be set globally (on <html>) or locally on any element (e.g., <p dir="rtl">مرحبا</p>).
    • Mixing directions (bidirectional text) is supported: 
      <p>English <span dir="rtl">مرحبا</span> continues here.</p>
    • dir="auto" lets the browser guess the direction based on content: 
      <p dir="auto">Hello!</p>
<p dir="auto">שלום!</p>
  • 19.3. Character Encoding: <meta charset="UTF-8">

    Always specify UTF-8 encoding to support all languages and symbols. Place the <meta charset="UTF-8"> tag at the top of your <head>. 

    <head>
  <meta charset="UTF-8">
  ...
</head>
    • UTF-8 covers most characters and symbols in the world, preventing display issues and "mojibake".
    • Avoid legacy encodings like ISO-8859-1 or Windows-1252 unless necessary for backward compatibility.
    • If you don’t specify encoding, browsers may guess incorrectly, causing garbled text.
  • 19.4. Localizing Content and Attributes
    • Translating visible text: Use the correct language and direction for all content.
    • Localizing attributes: Translate alt text, title attributes, labels, and ARIA attributes for accessibility. 
      <img src="cat.jpg" alt="Chat assis" lang="fr">
    • Date, time, and numbers: Format as per locale using JavaScript or server-side libraries. 
      <time datetime="2025-06-28">June 28, 2025</time>
                
      <script>
  // Example: Display today's date in user's locale
  const localDate = new Date().toLocaleDateString(navigator.language);
  document.body.innerHTML += localDate;
</script>
    • Forms: Translate all placeholders, labels, and validation messages.
    • Fonts: Choose fonts that fully support your character sets (e.g., Noto Sans, Arial Unicode MS).
  • 19.5. Multilingual Site Structure & hreflang
    • URL structure options:
      • Subdirectories: /en/, /fr/, /ar/
      • Subdomains: en.example.com, fr.example.com
      • Query parameters: ?lang=en
    • Indicate alternate languages with hreflang:

<link rel="alternate" hreflang="en" href="https://example.com/en/">
      • Helps search engines show the right language version to users.
      • Use correct language-region codes, e.g., en-US, en-GB, sw-TZ.
    • Provide language switchers: Let users easily pick their preferred language.

  • 19.6. Accessibility and Screen Readers
    • Correct lang and dir attributes improve accessibility for users with assistive technology.
    • Use semantic HTML to ensure content is understandable in any language.

20. Deprecated and Obsolete Tags
  • 20.1. What Are Deprecated and Obsolete Tags?

    Deprecated tags are HTML elements that are no longer recommended for use and may be removed in future versions of HTML. Obsolete tags are completely removed from the specification and should not be used at all. Using these tags can cause inconsistent rendering across browsers and future compatibility issues.

    • Browsers may still support some deprecated tags for backward compatibility, but their use is discouraged.
    • Rely on modern HTML and CSS for layout, styling, and dynamic effects.
  • 20.2. Common Deprecated & Obsolete Tags
    • Examples:
      • <font> (use CSS for text styling instead)
      • <center> (use CSS text-align: center; or flexbox)
      • <marquee> (no direct replacement; use CSS animations or JavaScript)
      • <big>, <strike>, <tt>, <u> (for underlines, use CSS text-decoration instead)
      • <applet>, <basefont>, <dir>, <isindex>, <noframes>, <s>, <spacer>
    • Using these tags can cause accessibility issues and unpredictable behavior in modern browsers.
    • Reference: MDN Web Docs: Obsolete and Deprecated Elements
  • 20.3. Modern Alternatives for Deprecated Tags
    • <font>: Use CSS for color, size, and font: 
      <span style="color: red; font-size: 20px; font-family: Arial;">Text</span>
    • <center>: Use CSS for alignment: 
      <div style="text-align: center;">Centered Text</div>
      or use Flexbox: 
      <div style="display: flex; justify-content: center;">Centered</div>
    • <marquee>: Use CSS animations: 
      <div class="marquee">Scrolling text</div>
<style>
.marquee {
  width: 200px;
  overflow: hidden;
  white-space: nowrap;
  animation: marquee 5s linear infinite;
}
@keyframes marquee {
  0%   { transform: translateX(100%);}
  100% { transform: translateX(-100%);}
}
</style>
    • Semantic alternatives: For <u> use <span style="text-decoration: underline;">.
      For <s>, use <del> for deletions, and <ins> for insertions, to improve semantics and accessibility.
  • 20.4. Deprecated Attributes
    • Many old attributes are now deprecated. Use CSS instead.
      • <table border="1"> → border: 1px solid #000; in CSS
      • <img border="0"> → img { border: none; }
      • <input align="right"> → float: right; or text-align: right; in CSS
    • Avoid using inline attributes for presentation; separate structure (HTML) from style (CSS).
  • 20.5. Browser Support and Forward Compatibility
    • Deprecated tags may still work in some browsers, but can be removed at any time.
    • Relying on obsolete tags risks your website breaking in the future.
    • Always use standards-based, modern HTML and CSS for new projects.
  • 20.6. Accessibility and SEO Impacts
    • Deprecated and obsolete tags often lack semantic meaning, reducing accessibility for screen readers and assistive tech.
    • Modern, semantic HTML improves search engine understanding and ranking.
    • Example: Use <strong> or <em> instead of <b> or <i> for meaning, not just appearance.
  • 20.7. Real-World Example: Migrating Deprecated Tags

    Before (deprecated):

    <center>
  <font color="blue" size="5">Welcome to My Site!</font>
</center>

    After (modern):

    <div style="text-align: center;">
  <span style="color: blue; font-size: 2em;">Welcome to My Site!</span>
</div>
    • The modern version uses semantic, standards-based HTML and CSS for layout and style.
  • 20.8. Best Practices for HTML Maintenance
    • Regularly audit your codebase for deprecated tags and attributes.
    • Use validators like W3C Markup Validation Service to detect obsolete code.
    • Refactor legacy HTML to modern standards to improve maintainability, accessibility, and future compatibility.

23. Microdata and Structured Data
  • 23.1. Microdata: itemprop, itemscope, itemtype for SEO

    Microdata is a way to add extra meaning (semantics) to your HTML content, which helps search engines better understand your site and display rich results (like star ratings, product info, etc.).

    • Basic Example: 
      <div itemscope itemtype="https://schema.org/Person">
  <span itemprop="name">Ada Lovelace</span>
  <img itemprop="image" src="ada.jpg" alt="Ada Lovelace">
  <span itemprop="jobTitle">Mathematician</span>
</div>
    • Key attributes:
      • itemscope: Defines that the element contains microdata.
      • itemtype: Specifies the type of item (use Schema.org URLs).
      • itemprop: Names the property being described (like name, image, etc.).
    • Benefits: Enhanced search results, better SEO, and improved accessibility for machines.
    • More complex example (Product): 
      <div itemscope itemtype="https://schema.org/Product">
  <span itemprop="name">Coffee Mug</span>
  <img itemprop="image" src="mug.jpg" alt="Coffee Mug">
  <span itemprop="description">A large, sturdy mug for coffee lovers.</span>
  <span itemprop="offers" itemscope itemtype="https://schema.org/Offer">
    Price: <span itemprop="price">12.99</span> USD
  </span>
</div>
    • Explore more schemas at Schema.org
  • 23.2. Structured Data with JSON-LD

    JSON-LD (JavaScript Object Notation for Linked Data) is the recommended way to add structured data for SEO. It's easy to read, doesn't clutter your HTML, and is supported by Google and other search engines.

    • Basic Example (Organization): 
      <script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "Organization",
  "name": "Ada Tech",
  "url": "https://adatech.com",
  "logo": "https://adatech.com/logo.png"
}
</script>
    • Benefits:
      • Does not affect the visible HTML structure.
      • Recommended by Google for rich results and easier maintenance.
      • Can describe almost any entity: articles, products, events, people, etc.
    • Test your structured data: Google Rich Results Test
  • 23.3. Real-World Example: Microdata vs. JSON-LD

    Microdata example (Recipe):

    <div itemscope itemtype="https://schema.org/Recipe">

24. Custom Data Attributes
  • 24.1. Using data-* Attributes for Storing Extra Information

    Custom data attributes (attributes that begin with data-) allow you to store extra information on any HTML element without using non-standard attributes or affecting the element’s presentation.

    • Syntax: data-*, where * is replaced by your chosen name (letters only, case-insensitive).
    • Example: 
      <div data-user-id="123" data-role="admin">
  User: Alice
</div>
    • Data attributes are valid on any element and do not affect layout or styling by default.
    • Useful for attaching extra information to elements for use in scripts, widgets, or dynamic apps.
  • 24.2. Accessing Data Attributes with JavaScript

    Data attributes are easily accessible in JavaScript through the dataset property on DOM elements.

    • Example: 
      <button id="myBtn" data-action="delete" data-item-id="42">Delete</button>

<script>
  const btn = document.getElementById('myBtn');
  // Access with the dataset property (camelCase for hyphens)
  console.log(btn.dataset.action);   // "delete"
  console.log(btn.dataset.itemId);   // "42"
</script>
    • The dataset property is an object with all data-* attributes as properties.
    • Setting data attributes in JavaScript: 
      btn.dataset.status = "active"; // Adds data-status="active"
    • Data attributes are often used for storing IDs, types, or state for JavaScript-driven interfaces, widgets, or libraries.
